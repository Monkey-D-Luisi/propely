# Fix Service Audits Workflow

## Overview

This workflow reads the three service audit reports generated by `audit services`, implements all fixes from each report, creates one commit per service, and opens a single pull request containing all commits.

## Trigger Command

**Command:** `fix service audits`

## Operating Mode (Mandatory Autonomy)

The agent must execute this workflow **end-to-end without waiting for user confirmation between steps**. Only stop and ask the user if there is a hard blocker that cannot be resolved locally (e.g., missing credentials, external system outage, or contradictory rules).

## Workflow Steps

### Step 0: Sync with Main

```bash
git checkout main && git pull origin main
```

### Step 1: Locate Service Audit Reports

1. Read all three reports:
   - `docs/audits/service-ai-api-audit.md`
   - `docs/audits/service-orgs-api-audit.md`
   - `docs/audits/service-web-audit.md`
2. If any report does not exist, inform the user and suggest running `audit services` first.
3. Parse the **Prioritized Action Plan** table from each report.
4. Collect all rows where `Status` = `Not started` from all three reports.
5. If no items remain across all reports, inform the user and stop.

### Step 2: Create a Shared Feature Branch

```bash
git checkout -b fix/service-audits-batch
```

### Step 3: Create Task and Walkthrough Documentation

1. Determine the next `ft-NNNN` ID by scanning `docs/tasks/ft-*.md`.
2. Create `docs/tasks/ft-<NNNN>-fix-service-audits.md`:
   - Include all three services and their action item counts in the Requirements section.
   - List every action item to be processed grouped by service.
3. Create `docs/walkthroughs/ft-<NNNN>-fix-service-audits.md`.

### Step 4: Process Service — ai-api

For each `Not started` action item in `docs/audits/service-ai-api-audit.md`, in priority/table order and respecting dependencies:

#### 4a. Implement the remediation

Follow Clean Architecture layer order:
1. Domain
2. Application
3. Infrastructure
4. Api

Write tests alongside production code. Reference `.agent/rules/testing-standards.md` for test patterns.

#### 4b. Update the audit report

Change each action item's `Status` from `Not started` to `Done`.

#### 4c. Run quality checks

```bash
dotnet build services/ai-api/SaasTemplate.AiApi.sln
dotnet test services/ai-api/SaasTemplate.AiApi.sln
```

All checks must pass before proceeding. If a test fails, fix it before continuing.

#### 4d. Commit all ai-api changes

```bash
git add <specific-ai-api-files> docs/audits/service-ai-api-audit.md
git commit -m "fix(ai-api): address service audit findings (#ft-<NNNN>)"
```

### Step 5: Process Service — orgs-api

Same sub-steps (5a–5d) as Step 4, targeting `services/orgs-api/`.

```bash
dotnet build services/orgs-api/SaasTemplate.OrgsApi.sln
dotnet test services/orgs-api/SaasTemplate.OrgsApi.sln
```

Commit:
```bash
git add <specific-orgs-api-files> docs/audits/service-orgs-api-audit.md
git commit -m "fix(orgs-api): address service audit findings (#ft-<NNNN>)"
```

### Step 6: Process Service — web

Same sub-steps (6a–6d) as Step 4, targeting `apps/web/`.

```bash
cd apps/web && npm run build && npm test
```

Commit:
```bash
git add <specific-web-files> docs/audits/service-web-audit.md
git commit -m "fix(web): address service audit findings (#ft-<NNNN>)"
```

### Step 7: Update Documentation

1. Fill in the walkthrough with summary, decisions, files changed, tests, verification results.
2. Mark the task file as `DONE` with all DOD checkboxes checked.
3. If all items across all three reports are now `Done`, update each report's metadata `Status` to `Complete`.

Commit:
```bash
git add docs/tasks/ft-<NNNN>-*.md docs/walkthroughs/ft-<NNNN>-*.md docs/audits/service-*.md
git commit -m "docs(audit): mark service audit fixes complete (#ft-<NNNN>)"
```

### Step 8: Push and Create Pull Request

```bash
git push -u origin fix/service-audits-batch
```

Create a PR following the PR template at `.github/PULL_REQUEST_TEMPLATE.md`:

- **Title:** `fix(audit): address all service audit findings`
- **Body:** List all action items processed per service with counts, combined testing results, and summary of what was fixed.
- Use `gh pr create`.

### Step 9: Report to User

1. Print a summary table showing each service, its action item count, and commit hash.
2. Report total test results (ai-api, orgs-api, web).
3. Print the PR URL.

## Skipping a Service

If a service has no `Not started` items, skip it entirely. Do not create an empty commit for that service.

## Error Handling

### Build/Test Failure

1. Fix the failure before continuing.
2. Include the fix in the same service commit.
3. Document the issue in the walkthrough.

### Cross-Service Dependencies

If a fix in one service depends on changes in another:
1. Process the dependency service first.
2. Document the dependency in the walkthrough.

### Partial Completion

If the agent cannot complete all items in a single session:
1. Commit and push whatever is completed so far.
2. Leave remaining items as `Not started` in the audit reports.
3. Note the partial status in the walkthrough and PR body.
4. The user can re-run `fix service audits` to continue processing remaining items.
