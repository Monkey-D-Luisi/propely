## Review Threads

### MUST_FIX

#### 1. PS1:107 - SSRF: No URL validation before following catalog entry URL
- **Source:** gemini-code-assist[bot] (security-medium)
- **Issue:** The PS1 script follows `catalogEntry` URLs without validating they start with `http`. An attacker controlling NuGet metadata could trigger requests to internal/file URLs. The bash script already validates with `grep -q '^http'`.
- **Resolution:** Add `-and $catalogEntry -like 'http*'` check to match bash script behavior.
- **Status:** [x] Fixed

#### 2. Hash computation parity (CI vs PS1 vs SH)
- **Source:** Copilot (.github/workflows/ci.yml:318, PS1:275)
- **Issue:** The PS1 script hashes individual file hash strings (hex only), while CI/bash hash the `sha256sum` output (hash + filepath). Additionally, bash uses absolute paths while CI uses relative paths. This means a hash generated by PS1 will never match CI, and bash-generated hashes may also differ from CI due to path differences.
- **Resolution:** Align all three to hash only the sorted hex digests (no filenames) for cross-platform consistency.
- **Status:** [x] Fixed

### SHOULD_FIX

#### 3. PS1:22-28 - Redundant repo root detection logic
- **Source:** gemini-code-assist[bot] + Copilot (both flagged)
- **Issue:** Lines 22-28 contain fallback logic that is unconditionally overwritten by line 30. Dead code.
- **Resolution:** Remove lines 22-28, keep only line 30.
- **Status:** [x] Fixed

#### 4. PS1:191 - Use ConvertFrom-Csv for npm CSV parsing
- **Source:** gemini-code-assist[bot]
- **Issue:** Regex-based CSV parsing is brittle with special characters. `ConvertFrom-Csv` is more robust and idiomatic.
- **Resolution:** Replace regex parsing with `ConvertFrom-Csv`.
- **Status:** [x] Fixed

#### 5. PS1:267 - Use UTF8NoBOM encoding
- **Source:** Copilot (PS1:267, THIRD_PARTY_NOTICES.md:1)
- **Issue:** PowerShell's `UTF8` encoding includes a BOM. The bash script doesn't produce a BOM, causing cross-platform inconsistency. BOM can break some parsers.
- **Resolution:** Change `-Encoding UTF8` to `-Encoding UTF8NoBOM`.
- **Status:** [x] Fixed

#### 6. PS1:275 - Hash generation scans full dirs instead of src/ only
- **Source:** Copilot
- **Issue:** PS1 recursively scans entire service directories and filters out 'tests', while bash explicitly scans `src/` subdirectories. Should align.
- **Resolution:** Change PS1 to scan only `src/` subdirectories, matching bash and CI.
- **Status:** [x] Fixed (merged into fix #2 - hash parity)

#### 7. PS1:175 + SH:119 - Exclude web@0.1.0 from npm output
- **Source:** Copilot (3 comments: PS1:175, SH:119, THIRD_PARTY_NOTICES.md:306)
- **Issue:** The project's own `web@0.1.0` package (UNLICENSED) appears in third-party notices. It's not a third-party dependency.
- **Resolution:** Add `--excludePackages "web@0.1.0"` to both scripts.
- **Status:** [x] Fixed

#### 8. SH:102 - Add bash v4+ requirement comment
- **Source:** gemini-code-assist[bot]
- **Issue:** `declare -A` (associative arrays) requires bash v4.0+. macOS ships with bash 3 by default. Should document this requirement.
- **Resolution:** Add requirement comment near the shebang.
- **Status:** [x] Fixed

#### 9. SH:34 - Remove `|| true` from dotnet/jq pipeline
- **Source:** gemini-code-assist[bot] (high)
- **Issue:** `|| true` suppresses jq failures, potentially hiding real errors (missing dotnet, broken JSON). With `set -euo pipefail`, failures should propagate.
- **Resolution:** Remove `|| true` from the jq command. Keep `2>/dev/null` on `dotnet list` to suppress stderr noise (asset file warnings). The `jq` `?` operators already handle missing/empty fields gracefully.
- **Status:** [x] Fixed

### SUGGESTION (Not Applied)

#### 10. SH:119 - Remove `2>/dev/null` from npx license-checker
- **Source:** gemini-code-assist[bot] (high)
- **Issue:** Reviewer suggests removing stderr suppression so failures are visible.
- **Rationale for not applying:** With `set -euo pipefail`, any real failure (npx not found, network error) causes the script to exit with a non-zero code. The `2>/dev/null` only suppresses stderr, which in this case contains known deprecation warnings from `inflight` and `glob@7` dependencies of license-checker. Removing it would clutter output with noise while providing no additional safety. The `--excludePackages` flag addition (fix #7) also redirects stderr, so this is a deliberate choice.
- **Status:** Not applied (documented rationale)
