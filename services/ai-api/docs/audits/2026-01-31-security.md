# Security Audit Report (2026-01-31)

## Summary
A security review was performed against the AI API Template to validate baseline requirements for authentication, authorization, input validation, transport security, configuration hygiene, data access safety, security headers, rate limiting, logging practices, and dependency vulnerability scanning.

**Overall posture:** Strong baseline coverage with centralized authorization policies, explicit JWT configuration guards, input validation at the API boundary, and security middleware enabled. One low-severity finding was identified regarding default development credentials in the local Docker Compose configuration. Dependency vulnerability scanning could not be completed due to missing tooling in the execution environment.

## Scope
- Security baseline review: `.agent.md`, `docs/standards/security-baseline.md`
- Presentation layer: authentication, authorization policies, request validation
- Configuration files: `.env.example`, `appsettings*.json`, `docker-compose.yml`
- Data access: repositories and query patterns
- Transport security: HTTPS/HSTS and security headers
- Rate limiting and logging practices
- Dependency vulnerability scanning

## Findings

### Low Severity
1. **Default development credentials in Docker Compose**
   - **Impact:** If the compose file is used in a shared or misconfigured environment, the default passwords could be abused to access local services.
   - **Evidence:** `docker-compose.yml` uses default values like `aiapi_dev_password` for PostgreSQL, RabbitMQ, and Redis when environment variables are not provided.
   - **Remediation:** Require explicit environment variables for passwords (remove defaults) or enforce `.env` usage in dev scripts. Add documentation warning that defaults must never be used outside local development.

### Informational / Observations
- **JWT authentication with centralized authorization policies is enforced.** JWT authority and audience must be configured at startup; policies are defined in `AuthorizationPolicies` and applied in controllers.
- **Anonymous access is guarded.** `Security:AllowAnonymous` is only allowed in Development/Testing environments and triggers a startup failure elsewhere.
- **Input validation is present at API boundaries.** `CreateWorkItemRequestValidator` enforces required fields and maximum lengths.
- **Transport security is enforced.** HTTPS redirection and HSTS are enabled outside Development/Testing.
- **Security headers are applied globally.** X-Content-Type-Options, X-Frame-Options, Referrer-Policy, and CSP are set for all responses.
- **Rate limiting is enabled.** Global rule enforces 100 requests per minute.
- **SQL injection protections are in place.** EF Core is used, and raw SQL uses parameterized inputs.
- **Logging avoids PII/secrets.** Logging statements use identifiers, not object serialization.

## Dependency Vulnerability Scan
- **Status:** Not completed.
- **Reason:** `dotnet` CLI was not available in the execution environment, so `dotnet list package --vulnerable` could not run.
- **Remediation:** Run `dotnet list package --vulnerable` in a developer environment or CI pipeline with the .NET SDK installed.

## Remediation Plan (Priority Order)
1. **(Low)** Remove or harden default development passwords in `docker-compose.yml`.
2. **(Informational)** Ensure dependency vulnerability scanning runs in CI using the .NET SDK.
